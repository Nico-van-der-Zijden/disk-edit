# D64 — 1541 disk image

A D64 is a byte-for-byte image of a Commodore 1541 5.25" floppy. It's the most common Commodore disk format and the one most other tools default to.

## Sizes

| Tracks | Bytes | With error bytes | Notes |
|---|---|---|---|
| 35 | 174,848 | 175,531 | Stock 1541; the default |
| 40 | 196,608 | 197,376 | Speeder-DOS extension (SpeedDOS, DolphinDOS, etc.) |
| 42 | 205,312 | 206,114 | Even rarer speeder-DOS extension |

If the file has the "+errors" size, the trailing 683 / 768 / 802 bytes hold one error byte per sector. The editor parses them but you can ignore them in most cases.

## Geometry

- **Tracks**: 35 (or 40 / 42 with a speeder)
- **Sectors per track**: 21 (tracks 1-17), 19 (18-24), 18 (25-30), 17 (31-35)
- **Bytes per sector**: 256
- **Directory track**: 18 (header at T18/S0, dir chain starts at T18/S1)
- **Default file interleave**: 10; **default dir interleave**: 3

## What you can do

Full read/write. Every disk-level and file-level feature works.

- Open, edit, save (writes a real D64)
- Add files via drag-drop, file-picker import, or paste from another disk
- Rename inline (double-click filename) — PETSCII bytes round-trip losslessly including reversed chars `$00-$1F`
- Sort directory, insert / remove rows, change file types, lock / unlock (`<` suffix), splat / unsplat (`*` prefix)
- View files as Hex / Disassembly / PETSCII / BASIC / Graphics / TASS / GEOS
- Run a selected PRG in the emulator via **File → Run in Emulator**
- View BAM (heat map) and Validate (rebuilds free-block counts + the bitmap from file chains)
- Scan for Lost Files in deleted-but-not-overwritten directory entries

## Speeder-DOS extended BAM

40-track and 42-track speeder D64s store the extended BAM (for the extra tracks) at a variant-dependent offset on track 18. The editor sniffs which speeder ROM produced the disk (SpeedDOS / DolphinDOS / etc.) and uses the matching offset.

This shows up in the BAM viewer's banner. The View BAM modal renders tracks 36-40 with the right offset, and Validate rewrites the BAM at the same offset.

## Soft write-protect

D64.TXT documents a "soft write-protect" byte at T18/S0 +`$02` — if it's `$01` instead of the standard `$41`, some ROMs refuse to write. The BAM viewer's banner flags this when present, and **Disk → Restore DOS Version Byte** under Disk Tools resets it to the standard value.

## Sub-directories

D64 doesn't have sub-directories. The directory is a flat list on track 18. (1581 D81 disks have sub-partitions; CMD Native / IDE64 CFS have real sub-dirs. None of those apply to D64.)

## Block count cap

The block-count field in a dir entry is 16-bit, but most CBM-DOS tools (and VICE's directory listing) cap the displayed value at 65,024 blocks. The editor enforces the same cap when you edit the block-count column.

## Saving

**Disk → Save** writes a `.d64` of the natural size for the track count (174,848 / 196,608 / 205,312 bytes). If the source had error bytes, the editor appends the same number of bytes from the in-memory error table.

## Known quirks

- A few really old D64s have garbage in unused bytes of dir entries — the editor reads them and leaves them alone unless you explicitly edit the row.
- REL files have side-sectors on a chain that the standard file walker can follow; the in-app "View as REL" viewer shows record-by-record decoding.
- VLIR (GEOS) files use a special structure: byte `$17` of the dir entry holds the GEOS structure type, byte `$18` the GEOS filetype. See the [GEOS](../features/geos.md) page for details.
